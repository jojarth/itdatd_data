# Site Reference

This page documents the site-specific tools used while writing ITD&TD pages.

Keep this page in `src/content/docs`. Starlight only treats files in the docs collection as normal documentation pages with the site layout, sidebar, search, table of contents, and routing. If this moved outside `docs`, it would need a custom page route and would stop behaving like the rest of the manual.

## Reusable Blocks

Use reusable Astro components when the same rules text, card, or table needs to appear in more than one place. This avoids copy/pasting and lets one edit update every reference.

Reusable blocks live in `src/components/reusable/`.

Example import:

```mdx
import KeywordFeatureCard from '../../../../components/reusable/KeywordFeatureCard.astro';
```

Example usage:

```mdx
<KeywordFeatureCard toc />
```

Props let reusable blocks vary the class-specific parts of the text.

```mdx
import OrderFeatureCard from '../../../../components/reusable/OrderFeatureCard.astro';

<OrderFeatureCard
  className="Cleric"
  traditions={['Military', 'Devotional', 'Stewardship']}
  toc
/>
```

Reusable blocks should render the exact markup they mean to insert. For example, use `<p>` tags for paragraphs inside `.astro` components instead of relying on Markdown paragraph parsing.

For reusable gameplay cards that should appear in the page table of contents, pass `toc` and optionally `tocDepth`.

```mdx
<KeywordFeatureCard toc tocDepth={2} />
```

The ToC helper in `src/remark-gameplay-card-toc.mjs` can create ToC entries for reusable components. For known reusable components, add a default title to `reusableTocTitles`. For one-off reusable components, you can pass a title from the page:

```mdx
<SomeReusableBlock toc tocTitle="Reusable Section Title" />
```

## Colored Tables

Use a colored table by wrapping a normal Markdown table in a `<div>` with a table color class.

```mdx
<div class="green-table">

| Level | XP To Level | Grit |
|:-----:|:-----------:|:----:|
| 1 | 0 | 1d4 |
| 10 | 450,000 | 9d4 + 1 |

</div>
```

Keep the blank lines between the `<div>` and the table. This helps MDX parse the Markdown table correctly.

Available table classes:

- `green-table`
- `blue-table`
- `red-table`
- `orange-table`
- `grey-table`
- `pink-table`
- `purple-table`
- `yellow-table`

Table colors are defined in `src/styles/custom.css`. To add a new color such as `azure-table`, add it to the shared table selector list, then define both light-mode and optional dark-mode CSS variables.

```css
.azure-table {
  --itdatd-table-border: #7dd3fc;
  --itdatd-table-header: #e0f2fe;
  --itdatd-table-header-text: #0c4a6e;
  --itdatd-table-row: #f7fcff;
  --itdatd-table-row-alt: #eef9ff;
  --itdatd-table-hover: #dff4ff;
}
```

## Spell Slot Tables

`SpellSlotTable` renders spell slot data from `src/content/data/spelldata/spell_slots/spell_slots.json`.

```mdx
import SpellSlotTable from '../../../../components/SpellSlotTable.astro';

<SpellSlotTable rank="A" colorTheme="blue-table" />
```

The `rank` prop chooses which spell slot progression to use:

- `A`
- `B`
- `C`
- `D`
- `E`

The `colorTheme` prop uses the same color classes as normal colored tables. Because `SpellSlotTable` renders its generated table inside the same wrapper pattern, changes to the shared colored table CSS also affect spell slot tables.

Spell slot tables include cantrip `Preparations` and `Casts` columns before leveled spell slots. The table header automatically groups those columns under `Cantrips` and groups `Level 1`, `Level 2`, and later spell slot columns under `Spell Slots`.

### Bolding Rows And Columns

Use `boldHeader` to bold the header bar.

```mdx
<SpellSlotTable rank="A" colorTheme="blue-table" boldHeader />
```

Use `boldColumn` or `boldColumns` to bold one or more columns. Column numbers are 1-based, so column `1` is `Class Level`.

```mdx
<SpellSlotTable rank="A" colorTheme="blue-table" boldColumn={1} />
```

Use `boldRow` or `boldRows` to bold one or more body rows. Row numbers are 1-based and do not include the header.

```mdx
<SpellSlotTable rank="A" colorTheme="blue-table" boldRows={[1, 5]} />
```

You can combine them:

```mdx
<SpellSlotTable
  rank="A"
  colorTheme="blue-table"
  boldHeader
  boldColumn={1}
/>
```

Live example:

<SpellSlotTable rank="A" colorTheme="blue-table" boldHeader boldColumn={1} />

If you add a new table color, also add it to the `colorTheme` type in `src/components/SpellSlotTable.astro` before using it as a prop.

## Gameplay Cards

Use `GameplayCard` for class summaries, feature callouts, special rules boxes, ancestry features, archetypes, and similar rules chunks.

```mdx
import GameplayCard from '../../../../components/GameplayCard.astro';
import FeatureSection from '../../../../components/FeatureSection.astro';
```

The number of `../` segments depends on where the page lives. From class pages in `src/content/docs/playersguide/05-classes/`, the import above is correct.

### Basic Card

```mdx
<GameplayCard
  color="purple"
  eyebrow="Class Feature"
  title="Feature Name"
  subtitle="A short summary of what the feature does."
>
  Write the feature text here.
</GameplayCard>
```

### Card Colors

Set the accent color with the `color` prop:

```mdx
<GameplayCard color="green" title="Class Gameplay">
  Write the card text here.
</GameplayCard>
```

Common colors:

- `green`: class or summary cards
- `purple`: feature cards
- `blue`: subclass cards
- `indigo`: ancestry cards
- `yellow`: archetype cards

Other defined colors:

- `red`
- `orange`
- `violet`
- `grey`
- `black`
- `brown`
- `azure`

Gameplay card colors are defined in `src/styles/custom.css` as classes like this:

```css
.gameplay-card--purple::before {
  background: #a855f7;
}
```

To add a new color, add a matching CSS block. `GameplayCard` accepts any string for `color`, so no TypeScript list needs to be updated.

```css
.gameplay-card--teal::before {
  background: #14b8a6;
}
```

Then use it:

```mdx
<GameplayCard color="teal" title="New Card Color">
  Write the card text here.
</GameplayCard>
```

### Header Fields

Gameplay cards support these header fields:

- `eyebrow`
- `subeyebrow`
- `title`
- `subtitle`

By default, cards render:

```txt
eyebrow
title
subtitle
```

Use `headerOrder` when you want a different order.

```mdx
<GameplayCard
  color="purple"
  title="Spellcasting"
  subeyebrow="1st Level Magic-User Feature"
  headerOrder={['title', 'subeyebrow']}
>
  Write the feature text here.
</GameplayCard>
```

### Cards In The Table Of Contents

Add `toc` to make a card title appear in the right-side table of contents.

```mdx
<GameplayCard
  color="purple"
  title="Spellcasting"
  toc
>
  Write the feature text here.
</GameplayCard>
```

The `toc` prop only works when `title` is a quoted string, like `title="Spellcasting"`.

By default, `toc` entries are added as level-three headings. Use `tocDepth={2}` when a card should appear as a higher-level section.

```mdx
<GameplayCard
  color="green"
  title="Magic-User Gameplay"
  toc
  tocDepth={2}
>
  Write the class gameplay overview here.
</GameplayCard>
```

## Spell Lists

Use `SpellList` to render filtered spell cards from the `data` collection.

```mdx
import { getCollection } from "astro:content";
import SpellList from "../../../../components/SpellList.astro";

export const allEntries = await getCollection("data");

<SpellList
  entries={allEntries}
  datatype="spell"
  level={1}
  className="Cleric"
  sortBy="title"
  sortDir="asc"
  showReverse
  showHeading={false}
  displayFields={['casting', 'shortDescription']}
/>
```

Useful filters:

- `datatype="spell"`
- `level={0}`
- `className="Magic-User"`
- `tag="some-tag"`

Useful list options:

- `showHeading={false}` hides the list's own heading.
- `sortBy="title"` sorts cards by their displayed titles.
- `sortDir="asc"` or `sortDir="desc"` controls sort direction.
- `showReverse` creates a separate card for each reverse spell form.

Useful display fields:

- `level`
- `casting`
- `school`
- `classes`
- `excerpt`
- `shortDescription`

When `classes` is displayed, class names are sorted alphabetically and comma-separated, regardless of their order in spell frontmatter.

### Showing Reverse Spells in a List

`showReverse` is opt-in. Without it, a reversible spell produces only its primary card. With it, the primary and reverse forms appear as separate alphabetized cards:

- **Bless** uses `title` and `shortDescription`, displays `Reverse: Curse`, and links to the top of the shared page.
- **Curse** uses `reverseTitle` and `reverseShortDescription`, displays `Reverse of: Bless`, and links directly to the Curse entry.

Both cards use the primary spell's level and class filters. The reverse card is generated for the list and does not create a second content file or route.

## Full Spell Pages

Full spell pages are rendered by `src/pages/data/[...slug].astro`.

That page:

- creates one route for each `data` collection entry
- uses the primary `title` as the page title
- shows the primary `shortDescription` and, when applicable, a `Reverse form` link in the page introduction
- shows spell metadata in a responsive grid
- sorts displayed class arrays alphabetically
- renders the spell's MDX rules below the metadata block
- passes inherited or overridden metadata to the reverse spell entry

The page title, introduction, and top metadata grid serve as the primary spell's complete header. The primary `SpellEntry` therefore renders only its rules sections. A reverse `SpellEntry` renders its own label, title, description, metadata, and rules so direct links remain self-contained.

Current full-page field order:

1. Spell Level
2. Casting
3. Range
4. Duration
5. Classes

To add a new full-page field, update the schema in `src/content.config.ts`, then render it in `src/pages/data/[...slug].astro`.

## Spell Entry Layout

Use `SpellEntry` to group each spell form's rules. Put `FeatureSection` components inside it for the effect, improvements, components, or other sections.

Inside a spell entry, every major `FeatureSection` begins with a two-part divider: a short form-colored accent followed by a neutral rule. Primary spell sections use amber, while reverse spell sections use violet. Markdown level-six headings render as compact, lightly tinted subsection bands with a stronger form-colored left edge. This creates the visual hierarchy **spell form → major rules section → subsection** without adding nested content cards.

### Spell Without a Reverse

```mdx
import FeatureSection from '../../../../../components/FeatureSection.astro';
import SpellEntry from '../../../../../components/SpellEntry.astro';

<SpellEntry title="Magic Missile">
  <FeatureSection title="Spell Effect">
    Write the spell effect here.
  </FeatureSection>

  <FeatureSection title="Spell Improvements">
    Write the spell's scaling here.
  </FeatureSection>

  <FeatureSection title="Components">
    Write the spell components here.
  </FeatureSection>
</SpellEntry>
```

The page header displays Magic Missile's title, short description, and metadata. Its primary `SpellEntry` begins directly with the rules, avoiding a repeated `Spell / Magic Missile` heading. `SpellEntry` still creates a lowercase anchor from its title; for example, Magic Missile receives `#magic-missile`.

### Primary and Reverse Entries

Keep the primary and reverse forms in the same MDX file, but give each form its own `SpellEntry` and rule sections. Their effects, improvements, and components can then change independently.

```mdx
import FeatureSection from '../../../../../components/FeatureSection.astro';
import SpellEntry from '../../../../../components/SpellEntry.astro';

<SpellEntry title="Bless">
  <FeatureSection title="Spell Effect">
    Write the Bless effect here.
  </FeatureSection>

  <FeatureSection title="Spell Improvements">
    Write the Bless improvements here.
  </FeatureSection>

  <FeatureSection title="Components">
    Write the Bless components here.
  </FeatureSection>
</SpellEntry>

<SpellEntry
  title="Curse"
  summary="Afflicts foes with divine condemnation."
  variant="reverse"
  metadata={props.reverseMetadata}
>
  <FeatureSection title="Spell Effect">
    Write the Curse effect here.
  </FeatureSection>

  <FeatureSection title="Spell Improvements">
    Write the Curse improvements here.
  </FeatureSection>

  <FeatureSection title="Components">
    Write the Curse components here.
  </FeatureSection>
</SpellEntry>
```

The page header serves as Bless's entry header and includes a `Reverse form: Curse` link. The detail page supplies `props.reverseMetadata` automatically. Passing it to the reverse `SpellEntry` displays a complete metadata grid when a reader follows that link or clicks the Curse list card.

`SpellEntry` props:

- `title`: required entry title; also creates the default anchor.
- `summary`: optional description shown beneath a reverse entry title; primary descriptions come from frontmatter.
- `variant="reverse"`: marks the entry as the reverse form and applies its distinct accent.
- `label`: optionally replaces the default reverse-entry label.
- `id`: optionally replaces the automatically generated anchor.
- `metadata={props.reverseMetadata}`: displays the resolved reverse metadata grid.

## Spell Frontmatter

Spell files live under `src/content/data/spelldata/spell_list/`. The allowed fields are defined in `src/content.config.ts`.

### Standard Spell Frontmatter

```yaml
---
datatype: spell
title: Snap Spark
level: 0
casting: 1 Master Action; Phase 3
range: 30 feet
duration: Instantaneous
classes:
  - Magic-User
shortDescription: Snapping your fingers, you cause a spark to harm a foe.
---
```

### Reversible Spell Frontmatter

```yaml
---
datatype: spell
title: Bless
shortDescription: Bolsters allies with divine favor.
reverseTitle: Curse
reverseShortDescription: Afflicts foes with divine condemnation.
level: 1
casting: 1 Master Action; Phase 4
range: 30 feet
duration: 1 minute
classes:
  - Cleric
  - Theurge
---
```

Reverse spell fields:

- `reverseTitle`: enables the reverse form and supplies its list-card title.
- `reverseShortDescription`: supplies the reverse form's list-card description.
- `reverseCasting`: optional reverse casting override.
- `reverseRange`: optional reverse range override.
- `reverseDuration`: optional reverse duration override.

Spell level and classes always inherit from the primary form. Casting, range, and duration also inherit by default. Add only the overrides that differ:

```yaml
reverseCasting: 1 Action; Phase 3
reverseRange: 60 feet
reverseDuration: 3 rounds
```

The resolved values appear in the reverse entry's metadata grid. Omitting an override keeps the corresponding primary value.

```bash
npm run dev
```

```bash
rm -rf .astro dist
```
